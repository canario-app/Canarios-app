**Dónde trabaja normalmente:** `backend/` y, cuando corresponda, `docs/api.md`.

1. Crear una rama por tarea, por ejemplo `backend/registro-canarios`.
2. Trabajar en la API y sus funciones dentro de esa rama.
3. Subir los cambios y abrir un PR hacia `main` con lo que se hizo y cómo se probó.
4. Pedir revisión a otro integrante de Backend cuando corresponda.
5. Si cambia una respuesta de la API, avisar a Frontend; si cambia la base de datos, coordinar con BD.
